# 《梦与非梦》工作规范

## 1. 先读什么

1. `docs/讨论记录.md` 作者已定的决定，和其他文档冲突时以它为准。
2. `docs/待确认.md` 最后两节，看哪些问题还开着、默认选了什么。
3. `docs/剧情线路图.md` 全部路线。
4. `docs/史实核查_第三轮.md` 最近一次读原文的结果。
5. 要动的那一幕在 `梦与非梦.html` 里的全部场景。

## 2. 写作规则（每一句都要守）

- 不用破折号（——）。
- 不用冒号引出一串列举。要列就分句写，或者在文档里用列表。
- 不用“不是 X，而是 Y”，也不用“与其说……不如说”“而非”这类对举。
- 第二人称“你”要克制。写“你”看见的、做的，不替“你”下判断，不写“你感到愧疚”。
- 选项之前先把情境铺好。玩家要知道这一步关系到谁、历史上发生了什么，才给选择。
- 情绪靠细节，比如手里的铅笔、窗上的影子、六十四元工资，不直说。
- 受害者要在场。有人挨打、被关、死掉的场景，要写出具体的人（年龄、工种、一个动作），不能只有数字。
- 人名、地名、职务、日期按史料写，不确定的写进史料注并标“有争议”。
- IF 线的事后谈要做逻辑审查。走了 IF 线以后，后文、尾声、人物结局里凡是假定历史线的说法（谁判了几年、谁当了副主席、“王洪文”这个名字是否还会被人提起）都要按这条线改，`after`/`EPI` 里用 `has()` 判断。

## 3. 史料标注

每一场的 `src` 和 `ctx`（背景面板）里，每一条都带一个标签：

- `<span class="tag hist">史实</span>` 有出处的事实，后面写出处（书名、章、篇名；网上的写“搜索摘要”）。
- `<span class="tag disp">有争议</span>` 各说不一，把几种说法和来源都写上，并说游戏取了哪一种。
- `<span class="tag fict">虚构</span>` 游戏演绎或梦里多出来的路，要说清哪部分是虚构。
- 背景面板里的作者观点用 `<span class="tag disp">解释</span>`。

## 4. 版权（硬性）

- 仓库是公开的。受版权保护的书（李逊《革命造反年代》、黄金海《十年非梦》等）**一个字都不能提交**。读书只在会话临时目录里读，笔记也留在临时目录。
- 游戏和文档里只能转述，引自这些书的地方注明“（转述）”和章号。短语级的原话（几个字的口头语）可以作为当事人语录出现，不要成段搬。
- `sources/` 只放公开文本（判决书、公社宣言之类），每个文件写明来源。
- main 分支上已经有作者放的 epub/PDF，不要把它们带进工作分支，也不要在工作分支里引用它们的路径。

## 5. 分支与提交

- 只在 `act2-draft` 上工作，不推 main，不开 PR，除非作者明说。
- 每完成一个阶段就提交并推送：`git push -u origin act2-draft`，网络失败按 2、4、8、16 秒重试。
- 提交信息用中文，一句话说清改了什么，结尾加作者要求的署名行。
- 没法自己决定的事写进 `docs/待确认.md` 新的一节，写明默认选了什么，然后按默认继续做。

## 6. 引擎约定

全部代码在 `梦与非梦.html` 最后一个 `<script>` 里。

- **场景** `SC.key = {act, tl, tone, stamp, place, title, ctx, text, choices, src, end, death, verdict, after, persona, branch, ifend, endKey}`。
  - `text`、`ctx`、`title`、`choices` 都可以是函数，按 `has()`/`any()`/`ax()` 拼不同文字。
  - 选项 `{t, set, a66, a77, next, grown}`。`set` 是这一步记下的事实；`a66`/`a77` 是 1967 年和 1977 年两种档案写法；`grown:true` 表示“梦里多出来的一条路”。
  - `death:true` 是提前结束的局，必须有 `after`（后来）和 `verdict`（结论）。`end:true` 是一幕的结尾。
  - `ifend` 标 IF 线所属，`branch` 标跨幕延续的支线（k1 到 k6）。
- **状态** `st`：facts、archive、log、last、path、cps、cp、told、startNote、branch、ifend。存在 localStorage 的 `mfm-state`、`mfm-dreams`、`mfm-ach`。
- **回响** `ECHO[flag] = {fx, w:{voice, hand, clean, ladder}}`。每个 `set` 都要在 ECHO 里有一条，`fx` 是一句直接后果，`w` 是四项分量的增减。四项的名字是 放权（voice）、宽待（hand）、清白（clean）、赏识（ladder），解释在 `GLOSS.ax_*`，`axLink()` 生成可点开的链接。
- **历史上的选择** `HX[scene]` 写这一步历史上的王洪文怎么做的，带出处。
- **门** `DOORS` 和 `canA1`、`canA2`、`canA7`、`canA4`、`canSW`、`canD3`、`canC1` 等判断某条梦里的路开没开。种子是某个具体选择，开门要靠分量累积。`drifted()`（赏识不到 8）决定第三幕末能不能进北京。
- **结局与成就** `ENDINGS`（23 种）、`WCH`（16 种改变）、`COUPLE`（7 种组合）、`ACH`、`recordAch()`、`DOOR_REQ`（梦满三次后显示的开门条件）。
- **从某一幕开始** `PRESETS`（五种人）、`simulate()`、`startFrom()`。改了前三幕的选项或分量以后，要跑 `tests/presetvals.js` 确认五种人都还能进北京、数值不过分偏。
- **重新做梦** `redoList()` 给每一幕三个按钮：保留原来的（`restartAct`）、换一种人（`presetPanel`）、从头。
- **人物卡** `CH`、`CH_ALSO`、`charExtra()`；术语 `GLOSS`；图 `FIG`；尾声 `EPI`。
- **给新玩家的说明（1.6）** 新写一场时一并补上。`KNOWN[scene]` 正文下的“当时的人都知道”，一到三句；`OPTMEAN[set]` 选项下的小字，写这个做法在当时意味着什么，好选项也写代价；`PLAIN[glossKey]` 名词第一次出现时的白话；`ACTCAUSE[act]` 幕末页的历史因果和“接下来”；`DEATHWHY[scene]` 提前结束页的“为什么停在这里”和“历史上接下来”；`ROLES[glossKey]` 人名的头衔，按幕变；`ASKS` 让戏里的人问出来。说法要直接，解锁就写“解锁”，条件写成“宽待 ≥ 4”。
- 调试入口 `window.__mfm`（SC、ECHO、HX、ax、st、start、sim）。

## 7. 改完以后

1. 语法快检（见 `tests/README.md`）。
2. `grep -c '——' 梦与非梦.html` 不应增加；`git diff | grep '^+' | grep -E '而是|与其说|而非'` 应为空。
3. 跑 `tests/` 里与改动相关的脚本，至少 `policy.js`、`branchtest3.js`、`deaths6.js`、`start2.js`；改得多就跑 `walk.js 20`。要求 `errors []`、`overflow 0`。
4. 史实有改动的，在 `docs/史实核查_第三轮.md`（或新开一轮）记下来源和改了哪一场；有需要作者看的，记进 `docs/待确认.md`。
5. 提交、推送，用中文向作者汇报改了什么、哪些还要作者决定。
